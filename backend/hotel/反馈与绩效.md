# 酒店绩效管理系统 (Performance Management System)

## 🚀 快速启动

Bash

```
# 进入项目目录
cd backend/hotel

# 启动应用
./mvnw.cmd spring-boot:run

# 访问API文档 (Swagger UI)
http://localhost:8082/swagger-ui.html
```

**环境要求**：Java 21+、MySQL 8.0+、智谱AI API Key（用于NLP分析与建议生成）

------

## 📡 完整API接口列表

### 1. 客户评价提交

**POST** `/api/v1/feedback/submit`

JSON

```
{
  "customerName": "张三",
  "feedbackContent": "房间非常干净，前台办理入住很快，好评！"
}
```

- **功能**：接收原始评论，通过 AI 自动计算情感得分（Sentiment Score）并自动识别归属部门。
- **拦截机制**：情感分 ≤ -0.8 的极端差评将自动标记为 `needsReview = true`，进入待审池。

### 2. 评价审核管理 (恶意拦截) 🆕

| **方法** | **路径**                | **功能**                                                   |
| -------- | ----------------------- | ---------------------------------------------------------- |
| GET      | `/api/v1/audit/pending` | 获取待审核的人性化评价列表（仅显示内容、得分等核心信息）   |
| POST     | `/api/v1/audit/process` | 审核操作：`APPROVE`（释放计入绩效）或 `REJECT`（永久排除） |

### 3. 绩效计算与统计

| **方法** | **路径**                                  | **功能**                                      |
| -------- | ----------------------------------------- | --------------------------------------------- |
| POST     | `/api/v1/performance/calculate`           | 指定日期触发绩效计算。参数：`hotelId`, `date` |
| GET      | `/api/v1/performance/history`             | 查询历史绩效趋势（支持日期范围过滤）          |
| GET      | `/api/v1/performance/department/{deptId}` | 获取特定部门的详细绩效指标与 AI 建议          |

## 🧠 核心功能详细说明

### 🤖 智能 NLP 分析引擎

- **自动化归因**：AI 根据评论内容从数据库动态获取部门列表（房务部、工程部等），实现精准画像匹配。
- **情感计算**：将自然语言转化为 `-1.0` 到 `1.0` 的量化指标，作为绩效评分的基础数据。
- **动态兜底**：无法识别的评论自动分配至“业务部”供人工二次核实，防止数据丢失。

### ⚖️ 恶意评论拦截系统 (Security Shield)

- **自动判定**：在提交环节实时拦截。
- **审核工作流**：
  1. **拦截**：得分极低时设置 `reviewStatus = PENDING`。
  2. **隔离**：计算任务自动跳过 `needsReview = true` 的数据。
  3. **人工决策**：管理人员在 `AuditController` 下拉选择结论。
  4. **信任机制**：审核通过的数据（`APPROVED`）在下次计算时将无视分值限制，强制进入计分池。

### 📈 绩效评分算法

- **归一化处理**：将情感分（-1 到 1）映射为百分制（0 到 100）。
- **公式**：`Score = (SentimentScore + 1) / 2 * 100`。
- **三级预警**：
  - **GREEN** (≥ 80): 服务优良。
  - **YELLOW** (70-79): 存在隐患。
  - **RED** (< 70): 严重警告，触发 AI 改进建议。

------

## 🏢 部门与考核体系

### 参与考核部门

系统自动从数据库读取当前可用部门：

- **核心业务部**：房务部、前厅部、餐饮部、工程部、客房部、礼宾部。
- **管理/支持部**（不分配评论）：财务部、人力资源部、市场营销部。

### AI 管理建议生成

当部门绩效触发 **RED** 预警时，系统会自动汇总该日该部门的所有负面评价文本，调用 AI 生成针对性的管理改进方案。

## 🧪 测试用例

### 1. 正常好评流程

JSON

```
// POST /api/v1/feedback/submit
{
  "customerName": "王小二",
  "feedbackContent": "早餐的牛肉面非常好吃，厨师服务态度也很棒。"
}
// 预期：归类为“餐饮部”，得分 > 0.5，直接计入绩效。
```

### 2. 恶意差评拦截流程

JSON

```
// POST /api/v1/feedback/submit
{
  "customerName": "匿名用户",
  "feedbackContent": "垃圾酒店！全是蟑螂！！服务员态度极差！！"
}
// 预期：得分 < -0.8，status 变为 PENDING，needsReview 为 true。
```

### 3. 审核释放测试

- 调用 `/api/v1/audit/process?feedbackId=X&action=APPROVE`。
- 重新计算该日绩效，观察分数是否由于该条负面评价的加入而产生合理波动。

------

## 📊 数据库核心表

- **customer_feedback**：存储原始评价、AI 分数、审核状态、归属部门。
- **department_performance**：存储每日结算后的绩效指标、预警等级、趋势方向及 AI 改进建议。
- **sys_department**：部门定义及权重配置。
